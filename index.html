محاكي محرر SQL لمعاملات ACID

اكتب أوامر SQL ثم اضغط "تنفيذ" لمشاهدة تأثيرها على جدول Accounts مع دعم
BEGIN TRANSACTION / COMMIT / ROLLBACK للتدرب على التراجع والتثبيت.

المحتوى العملي — خطوات الواجب

  1. إنشاء جدول حسابات Accounts بالأعمدة Acc_no INT PRIMARY KEY وAcc_name VARCHAR(50) وBalance DECIMAL(10,2)، وإدخال بيانات حسابين على الأقل.
  2. تنفيذ معاملة تحويل رصيد: ابدئي المعاملة ثم اخصمي مبلغًا من الحساب الأول.
  3. إضافة المبلغ نفسه إلى حساب آخر ضمن المعاملة نفسها.
  4. التراجع عن العملية باستخدام ROLLBACK والتحقق من عودة الأرصدة.
  5. إعادة تنفيذ التحويل نفسه في معاملة جديدة مع التثبيت باستخدام COMMIT.

نفّذي الخطوات على مراحل، وأرفقي صور الشاشة للأوامر والنتائج. استخدمي SELECT * FROM Accounts لعرض الأرصدة. في هذا التمرين يجب أن يكون التحويل بين حسابين مختلفين وبمبلغ موجب لا يتجاوز الرصيد؛ هذه قواعد التمرين وليست ضمانًا تلقائيًا من SQL.

مؤشرات الخطوات توثّق التنفيذ على هذا الجهاز، وليست درجة نهائية أو إثباتًا لهوية المنفّذة. يبدأ المحرر دون حل جاهز.

CREATE TABLE Accounts (...) INSERT INTO Accounts VALUES (...) UPDATE Accounts SET Balance = Balance ± 500 WHERE Acc_no = ... SELECT * FROM Accounts; BEGIN TRANSACTION; COMMIT; ROLLBACK;

خصائص ACID وحدود المحاكاة

Atomicity: التراجع يعيد جميع تعديلات المعاملة. وعند حدوث خطأ تُمنع متابعة التعديل أو التثبيت حتى تنفيذ ROLLBACK.

Consistency: يتحقق التمرين من كفاية الرصيد ووجود الحسابين وتساوي الخصم والإضافة قبل التثبيت.

Isolation: عزل المعاملات المتزامنة مفهوم نظري هنا؛ لا تختبر هذه الصفحة معاملات متعددة متزامنة. حفظ نسخة للتراجع لا يثبت تحقق العزل.

Durability: تُحفظ البيانات المثبتة محليًا في تبويب المتصفح وتُستعاد عند تحديثه، إن كان التخزين متاحًا. يُلغى أي تعديل غير مثبت عند التحديث. هذا تخزين تعليمي مؤقت، وليس ضمان استمرارية قاعدة بيانات إنتاجية أو حفظًا بعد إغلاق التبويب.

المحاكي يدعم صيغ الأوامر المعروضة فقط، وليس محرك SQL كاملًا. أنشئي الجدول وأدخلي الحسابات قبل بدء معاملة التحويل؛ كل معاملة تحويل تتكون من خصم واحد وإضافة مساوية له إلى حساب آخر.
